# ТИШЕ / HUSH на компьютере (.exe)

Игра — это веб-сборка. Настольная версия — тонкая оболочка Electron вокруг неё: тот же самый `dist/`, но в своём
окне, со своим значком, без адресной строки и без интернета для запуска. Ничего в игре не меняется, поэтому
кооператив, микрофон и эхо работают так же, как в браузере.

## Что внутри оболочки и почему так

- **`hush://app/` вместо `file://`.** Игра построена на `getUserMedia` и WebRTC, а им нужен настоящий origin:
  у `file://` он «непрозрачный», и микрофон там ведёт себя непредсказуемо. Схема зарегистрирована как
  `standard` + `secure`, значит страница считается защищённым контекстом — как на `https://sanlaran.github.io`.
- **Никакого доступа к диску.** Обработчик запросов отдаёт файлы только из `dist/` (и падает с 403 на `../`).
  `nodeIntegration: false`, `contextIsolation: true`, `sandbox: true` — страница не может дотянуться до Node.
- **Файлы читаются через `fs`, а не через `file://`.** Сборка упакована в `app.asar`, и обычный `file:`-адрес
  внутрь архива не смотрит, а пропатченный `fs` — смотрит. Ответ несёт правильный `content-type` и понимает
  `Range` (206/416): музыку играет `<audio>`, который перематывается и зацикливается, и без диапазонов
  зацикливание трека встаёт. Проверки на всё это — в `tests/round21x.test.mjs`, включая настоящий прогон
  обработчика на временной сборке.
- **Разрешения: микрофон и мышь.** `setPermissionRequestHandler` пропускает `media`/`audioCapture`, а с 3.1f
  `pointerLock` и `fullscreen` со своего origin и отказывает всему остальному (камера, геолокация, буфер обмена).
  Без `pointerLock` камера в игре не вертелась.
- **Один экземпляр.** Второй запуск не открывает второе окно (две копии дрались бы за микрофон), а поднимает
  уже запущенное.
- **Клавиши:** `F11` — полный экран, `F12` — инструменты разработчика, `Ctrl+R` — перезапуск, `F10` — сброс
  масштаба. Остальные клавиши — игре.
- **Звук с первого кадра:** включён `autoplay-policy=no-user-gesture-required`, титульная музыка не ждёт клика.

## Где что лежит

| файл | что делает |
| --- | --- |
| `electron/main.cjs` | окно, меню, клавиши, один экземпляр, разрешение на микрофон, обновление |
| `electron/preload.cjs` | единственный мост в страницу: `window.hushDesktop` — версия, проверка, скачивание, страница релизов. Больше ничего |
| `electron/update.cjs` | какая сборка новее и какой файл брать из релиза — чистая логика, тестируется (`tests/round30m`) |
| `electron/serve.cjs` | что можно прочитать (`dist/` и только он), типы файлов, `Range`, кто получает микрофон — чистая логика без Electron, поэтому тестируется |
| `electron/assets/icon.png` | значок окна и .exe (512×512) |
| `electron-builder.yml` | что и как упаковывается: установщик NSIS (на пользователя, без прав администратора) и portable x64 |
| `.github/workflows/desktop.yml` | сборка .exe в CI и выкладка артефакта |

## Собрать самому (Windows или Linux/macOS с Wine для .exe)

```bash
npm ci
npm run desktop        # собрать dist/ и запустить как приложение (проверить, что всё работает)
npm run desktop:win    # установщик + портативный .exe + .pak + манифест → release/
```

`desktop` и `desktop:win` ставят Electron и electron-builder через `npx --yes` при первом запуске (≈200 МБ
в кэш), поэтому в `package.json` их нет: веб-деплой остаётся лёгким. Версии закреплены: Electron **45.0.0**,
electron-builder **26.15.3** (и в `electron-builder.yml`, и в скриптах).

Разработка с горячей перезагрузкой: в одном терминале `npm run dev`, в другом
`HUSH_DEV_URL=http://localhost:5173 npm run desktop:dev`.

## Собрать в GitHub Actions (без своего Windows)

Actions → **Desktop (HUSH)** → **Run workflow**. Через ~5 минут:

- **скачать .exe:** в прогоне, внизу страницы, артефакт **HUSH-win-x64**;
- на теге `arena/*` всё это приезжает в **Releases**: `HUSH-Setup-….exe`, `HUSH-…-win-x64.exe`, `.pak` и манифест.

## Лаунчер и обновления (3.1d)

Игра ставится **установщиком** `HUSH-Setup-1.0.N.exe`: в профиль пользователя (без прав администратора), с
ярлыками на рабочем столе и в «Пуске». Первым открывается **лаунчер** (`launcher.html` — вторая страница той же
vite-сборки): ИГРАТЬ, строка обновления, «что нового» из тех же заметок, что в игре, две настройки («сразу
запускать игру», «игра на весь экран») и ссылки (папка игры, сайт, «сообщить об ошибке»). Пока открыто окно игры,
лаунчер спрятан; закрыл игру — он вернулся; закрыл лаунчер — приложение вышло.

Обновление в две скорости, потому что меняется почти всегда только игра:

| что | сколько | как |
| --- | --- | --- |
| **игра** (`dist/`) | ~7 МБ `.pak` | лаунчер скачивает, проверяет sha-256 и распаковывает рядом со старой в `%APPDATA%\HUSH\game\<версия>\`; следующее окно игры открывается уже на ней. Ничего не переустанавливается |
| **оболочка** (Electron + `electron/*.cjs`) | ~90 МБ установщик | только если поменялся её «отпечаток» (`shellId`: хэш `electron/*.cjs` + версия Electron). Качается в фоне в `%APPDATA%\HUSH\updates\` и ставится **тихо при выходе** (`/S --updated`) или сразу по кнопке «ОБНОВИТЬ СЕЙЧАС» (`--force-run` — и игра запускается снова) |

Как это устроено:

1. Каждый тег `arena/*` → workflow **Desktop (HUSH)** кладёт в релиз четыре файла: установщик, портативный exe,
   `hush-game-1.0.N.pak` и `hush-manifest.json` (`scripts/pack-game.cjs`: версия, раунд игры, размер и sha-256
   каждого файла, `shellId`). Релиз помечается **latest**.
2. Лаунчер при запуске и раз в три часа читает `github.com/SanLARAN/pinterest/releases/latest/download/hush-manifest.json`.
   Из манифеста берутся только имена, размеры и хэши — проверенные (`update.cjs: cleanManifest`); адреса для
   скачивания собираются из своего репозитория, не из файла.
3. `.pak` — свой формат без зависимостей (`electron/pak.cjs`): `HUSHPAK1` + gzip(заголовок с хэшем каждого файла +
   файлы). Распаковка отказывает пути наружу (`..`, диск, `\`), дублям имён без учёта регистра и любому
   несовпадению хэша. Копия считается целой, только когда последним записан маркер `.hush-ok`; недописанная
   копия не используется никогда — играем на встроенной. Хранятся текущая и предыдущая, остальные удаляются.
4. Если ИГРАТЬ нажали во время скачивания — кнопка ждёт («ЖДУ ОБНОВЛЕНИЕ…») и запускает игру сама, когда
   скачалось; рядом есть «играть без обновления».
5. Нет сети — «нет связи с GitHub — играем на том, что есть». Игра никогда не ждёт сеть.
6. В самой игре строка в углу меню говорит, если новая версия скачалась, пока ты играл: «ПЕРЕЗАПУСТИТЬ»
   перезагружает окно на неё (`hush:update:restart`).

**Портативная сборка** (`HUSH-1.0.N-win-x64.exe`) — тот же лаунчер и те же обновления игры; оболочку она
обновляет подменой своего файла. Важно: портативный exe при запуске распаковывается во временную папку, так что
подменять надо файл, который запустил игрок (`PORTABLE_EXECUTABLE_FILE`), а не `process.execPath` — так работало
до 3.1d, и подмена не доходила до настоящего файла.

Старые портативные сборки (3.0m–3.1c) ищут в релизе `.exe` с `x64` в имени — это по-прежнему портативный файл,
так что они обновятся как раньше и дальше уже будут с лаунчером.

| файл | что делает |
| --- | --- |
| `electron/updater.cjs` | состояние лаунчера: проверка, скачивание игры, скачивание оболочки (без Electron, тестируется) |
| `electron/content.cjs` | какие копии игры на диске, какая главная, установка, уборка, `shellId` |
| `electron/pak.cjs` | упаковка/распаковка `.pak` |
| `electron/net.cjs` | JSON и скачивание с sha-256 на лету, редиректы GitHub |
| `electron/preload-launcher.cjs` | мост лаунчера: `window.hushLauncher` |
| `launcher.html`, `src/launcher/` | сам лаунчер (`?demo=downloading` / `shell` / `error` — посмотреть в браузере без оболочки) |
| `scripts/pack-game.cjs` | `.pak` и манифест для релиза |

## Google Drive

Файл на диск кладёт шаг «Upload to Google Drive» — через `rclone` и **сервисный аккаунт**. Пока в репозитории
нет секрета, шаг молча пропускается (сборка при этом зелёная). Чтобы включить:

1. В Google Cloud создай сервисный аккаунт и скачай ключ в JSON (роль — не нужна, достаточно Drive API).
2. В Google Drive создай папку (например `HUSH`) и **поделись ею** с адресом сервисного аккаунта
   (`…@….iam.gserviceaccount.com`) с правами «Редактор». Скопируй **id папки** из адресной строки.
3. В GitHub: Settings → Secrets and variables → Actions
   - **Secret** `GDRIVE_SA` — содержимое JSON-ключа целиком;
   - **Variable** `GDRIVE_FOLDER` — id папки (или её имя, если оно уникально).
4. Перезапусти workflow: .exe окажется в этой папке.

Почему не «просто залить»: у меня нет доступа к твоему Google Drive — приложение Drive в этом чате выключено,
а заливать файл от твоего имени без твоего ключа нельзя. Схема с секретом делает это автоматически и без
хранения пароля в репозитории: ключ лежит только в секретах Actions.

## Ограничения

- Сборка **не подписана**: Windows покажет «SmartScreen: неизвестный издатель» — «Подробнее» → «Выполнить
  в любом случае». Подпись стоит денег (сертификат), поэтому её здесь нет.
- Только **x64**. ARM64 можно добавить строкой `arch: [x64, arm64]` в `electron-builder.yml`.
- Размер ~110–130 МБ: это Chromium. Для сравнения, Tauri дал бы ~5 МБ, но требует Rust и WebView2.
