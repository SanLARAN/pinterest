# Сайт игры (`site/`, 3.1s)

Отдельная страница рядом с игрой: https://sanlaran.github.io/pinterest/site/ — тот же ночной лес прямо на странице:
кликни — бросишь камень, зажми — крикнешь, и эхо проявит деревья (и того, кто между ними). Смена из четырёх ночей
на прокрутке, атлас тварей с живыми моделями из игры, голосование за тварь следующего обновления, альбом снимков
с фотоаппарата из игры (4.0) и все патчи с поиском.

## Запуск, сборка, выкладка

```bash
npm run dev          # тот же сервер, что у игры: http://localhost:5173/site/ (ссылки «Играть» ведут на ../ — в игру)
npm run build:site   # vite.site.config.js: корень site/, выход dist/site/, base './'
```

Workflow **Pages (HUSH)** собирает сайт после игры (`npm run build` → `npm run build:site`) и выкладывает вместе
с ней: игра — `/pinterest/`, сайт — `/pinterest/site/`. В `play/` сайт не попадает, поэтому его можно менять без
пересборки `play/` (проверка свежести `play/` в workflow от него не зависит).

Код игры сайт берёт прямо из `src/` (рендер, конфиг, атлас, тексты патчей), поэтому не расходится с игрой.

## Что на странице

- **Лес на фоне** (`stage.js`, `forest.js`) — кусок настоящего леса игры: те же `World.prototype.*` (сосны,
  сухостой, берёзы, пугала, лагерь, пять генераторов), тот же сонар-материал, импульсы, эхо-отпечатки и глаза.
  Клик — камень (импульс там, куда упал), удержание — голос: 0,2 с до начала, 1,6 с до крика. Микрофон —
  игровой (`src/audio/mic.js`, с калибровкой из игры), только если включить. 1485 деревьев: 15 из 1500 стояли
  ближе 3,6 м к треку камеры, и камера пролетала сквозь стволы.
- **Смена** (`timeline.js`) — прокрутка через 4 ночи по 8:00, 3 утра по 1:45 и последний рассвет 5:00; часы идут
  в настоящих длительностях, утро гаснет как лампочка, на 4-й минуте последней ночи «лес просыпается»,
  генераторы загораются по одному (`SHIFT_SEGMENTS`, `lightAt`, `gensLitAt`).
- **Атлас** (`atlas.js`, `plate.js`) — пластины игры (`src/ui/atlas3d.js`) и тексты `atlasData`: обе книги,
  главы, лента миниатюр, голоса тварей; колесо листает страницу, приближение — ctrl + колесо.
- **Голосование** (`votes.js`, `voteClient.js`, `mobs.js`, `mobVoices.js`) — шесть тварей-кандидатов с моделями
  и голосами. Один голос с устройства (или аккаунта игры, если вошёл), передумать можно; итоги видны после своего голоса.
- **Альбом** (`album.js`, 4.0) — кадры фотоаппарата из игры (`src/game/photo.js`), которые игрок сложил «В альбом»
  на экране конца смены (`src/ui/film.js`). Лежат в IndexedDB этого браузера (`hush-photos`, `src/core/photoStore.js`):
  сайт и игра на одном origin (`/pinterest/` и `/pinterest/site/`), поэтому страница читает то же хранилище —
  на сервер ничего не уходит. Группы по сменам, просмотр (← → Del Esc), скачать кадр / смену / всё как `.zip`
  (свой stored-zip без зависимостей), удалить, очистить (второе нажатие подтверждает). `#album` — прямая ссылка;
  при возврате во вкладку альбом перечитывается. В десктопной сборке (Electron) хранилище своё — там кнопки
  «В альбом» нет, только `.zip`.
- **Патчи** (`patches.js`) — весь `src/ui/news.js`: поиск со счётчиком и подсветкой, линии версий, ссылка на
  патч (`#v3.1r`), «новое с прошлого визита».
- Строки — только `i18n.js`, сразу `ru` **и** `en`; язык и звук помнятся в `localStorage` `hush.site.v1`.

## Урна голосования (Supabase)

`supabase/migrations/20261103180000_hush_mob_votes.sql` — таблица `hush_mob_votes` (закрыта, IP хранится только
солёным md5) и два RPC: `hush_mob_tally(p_device)` и `hush_mob_vote(p_mob, p_device)`; не больше 30 новых
голосов в сутки с одной сети. Применяется в Supabase → SQL Editor. Пока миграции нет, голос ждёт на устройстве
(«pending») и уходит позже сам. Список кандидатов в SQL и `MOB_IDS` в `voteClient.js` сверяет тест.

## Тесты и харнесс

- `tests/site.test.mjs`: паритет строк, кандидаты = SQL, модели тварей в node, таймлайн, клиент голосования на
  поддельном `fetch`, стиль дома (радиусы ≤ 4 px, шрифты, палитра) и ширина вёрстки на телефоне.
- **Голоса в тестах и харнессе не отправлять никогда**: в Playwright — `page.route(/supabase\.co/)` с поддельным
  ответом, в node — поддельный `fetch`.
- `?q=0.25` — фиксированный масштаб рендера (в SwiftShader кадр идёт 1–2 с). `window.__hushSite` — `stage`,
  `atlas`, `ballot`, `album`, `patches`, `engine`; после `scrollTo` ставить `stage.uSmooth = stage.u`, чтобы камера не догоняла.

## Грабли

- Небо (`createSky`, сфера r 140) обязано ездить за камерой (`sky.position.copy(camera.position)`): оставленное в
  начале координат, при дальней плоскости 170 м оно в 70 м от центра «прорезается» чёрным диском.
- Колонка из flex с `flex-wrap: wrap` меряет строку по самому широкому ребёнку, а не по ширине контейнера: полоса
  глав атласа (478 px) растянула страницу до 496 px на экране 390 px, и телефон уменьшил весь сайт на пятую часть.
  В мобильных правилах `flex-direction: column` — всегда с `flex-wrap: nowrap` (это проверяет тест).
- Подпись пластины и масштабная линейка (44–110 px + подпись) на телефоне в одну строку не влезают: линейка
  поднимается на строку выше, ширину линейки `atlas.js` кладёт в `--scale-w`.
- В харнессе SwiftShader на 1280×800 CSS-переходы на скрине могут быть ещё в прошлом состоянии (часы финала
  красные от «лес проснулся»). Цвет проверять через `getComputedStyle` после паузы, а не на глаз.
